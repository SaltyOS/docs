= Threads
:description: Thread Control Block, thread states, SchedContext binding, priority inheritance, FPU context, and sleep queue

A _thread_ is a schedulable execution context represented by a Thread Control Block (TCB).
Each TCB is a kernel object created by retyping untyped memory.
Threads are bound to a SchedContext for scheduling parameters and a VSpace for their address space.

== Thread Control Block

The TCB contains all per-thread kernel state:

[cols="1,1,3"]
|===
| Field | Type | Purpose

| `header` | `KernelObject` | Object header (type = `Tcb`, refcount).
| `state` | `ThreadState` | Current execution state.
| `priority` | `u64` | Effective deadline (may be boosted by PIP).
| `base_priority` | `u64` | Original deadline (unaffected by inheritance).
| `pip_donating_to` | `*mut Tcb` | TCB this thread is donating priority to.
| `vspace_root` | `*mut VSpace` | Page table root for this thread.
| `cspace_root` | `*mut CNode` | CSpace root CNode.
| `ipc_buffer` | `u64` | Virtual address of the thread's IPC buffer page.
| `kernel_stack` | `u64` | Kernel stack for syscall entry.
| `cpu_affinity` | `u32` | Pinned CPU (`0xFFFF_FFFF` = any).
| `sc` | `*mut SchedContext` | Bound scheduling context.
| `fault_endpoint` | `u64` | Capability address of fault endpoint.
| `bound_notification` | `*mut Notification` | Bound notification for combined IPC wait.
| `notification_dispatcher` | `u64` | Userspace dispatcher for notification delivery during Call.
| `reply_tcb` | `*mut Tcb` | Saved reply target (for server-side reply capability).
| `blocked_reason` | `Option<BlockedReason>` | Why the thread is blocked.
| `blocked_endpoint` | `*mut u8` | Endpoint the thread is blocked on.
| `fpu_state` | `XSaveArea` | Saved FPU/SIMD register state.
| `fpu_used` | `bool` | Whether this thread has used FPU since last context switch.
|===

== Thread States

[plantuml]
....
@startuml
skinparam defaultFontSize 11

state "Ready" as R : In the ready queue.\nWaiting for CPU time.
state "Running" as RUN : Executing on a CPU.
state "Blocked" as B : Waiting for an event\n(IPC, fault, timer, futex).

[*] --> I : retype / TCB_CONFIGURE
I --> R : TCB_RESUME
R --> RUN : scheduler\nselects
RUN --> R : preempted /\nyield
RUN --> B : IPC block /\nfault / sleep
B --> R : event arrives\n(message, signal,\ntimeout)
RUN --> I : TCB_SUSPEND
R --> I : TCB_SUSPEND
@enduml
....

[cols="1,3"]
|===
| State | Description

| `Inactive` | Not schedulable.  Newly created threads start here.
| `Ready` | In the ready queue, waiting for the scheduler to select it.
| `Running` | Currently executing on a CPU.
| `Blocked` | Waiting for a specific event.  The `blocked_reason` field identifies the cause.
| `Waiting` | Waiting on a notification (legacy alias for notification-specific blocking).
|===

== Blocked Reasons

When a thread enters `Blocked` state, the `blocked_reason` identifies the cause:

[cols="1,3"]
|===
| Reason | Cause

| `SendBlocked` | Waiting for a receiver on an endpoint.
| `RecvBlocked` | Waiting for a sender on an endpoint.
| `CallSendBlocked` | Call's send phase is waiting for a receiver.
| `ReplyWait` | Waiting for the server's reply after a Call.
| `FaultBlocked` | Waiting for a fault handler to reply.
| `NotificationWait` | Waiting on a notification.
| `TimerBlocked` | Sleeping via `NanoSleep`.
| `FutexBlocked` | Blocked on a futex wait.
| `FutexTimedBlocked` | Blocked on a futex wait with timeout.
| `SendTimedBlocked` | Timed send to an endpoint.
| `RecvTimedBlocked` | Timed receive from an endpoint.
| `VSpaceWait` | Waiting for a VSpace teardown to complete.
|===

== SchedContext

A SchedContext encapsulates scheduling parameters, decoupled from the thread identity:

[source,rust]
----
pub struct SchedContext {
    pub header: KernelObject,
    pub sc_lock_state: AtomicU8,  // per-SC spinlock
    pub budget: u64,              // max CPU time per period (ticks)
    pub remaining: u64,           // remaining budget in current period
    pub period: u64,              // replenishment interval
    pub deadline: u64,            // absolute deadline
    pub bound_tcb: *mut Tcb,      // bound thread
    pub consumed: u64,            // cumulative consumed time (ticks)
}
----

A TCB is bound to a SchedContext via `SC_BIND` (invoke label `0x31`).
The SchedContext determines _when_ the thread runs; the TCB determines _what_ it executes.

== Priority Inheritance Protocol (PIP)

When a high-priority thread blocks on a resource held by a lower-priority thread, the kernel temporarily boosts the holder's priority to prevent priority inversion.

=== Mechanism

. Thread A (high deadline) sends to an endpoint where thread B (low deadline) is the expected receiver but is not yet waiting.
. Thread A blocks.  The kernel records `A.pip_donating_to = B`.
. Thread B's effective priority (`priority` field) is set to A's deadline.
. When B completes the operation and A is unblocked, B's priority reverts to `base_priority`.

=== Properties

* Donation is transitive: if B is itself blocked on C, the donation propagates.
* Only one donation per thread is tracked at a time.
* Reversion is automatic when the blocking reason is resolved.
* PIP applies to the thread's TCB `priority` field, not the SchedContext directly.

== FPU/SIMD State

FPU and SIMD registers are managed via lazy context switching:

x86_64::
The kernel sets `CR0.TS` (or clears `CR0.MP`) after a context switch.
The first FPU instruction triggers a `#NM` (Device Not Available) exception.
The handler saves the previous thread's state via `XSAVE` and restores the current thread's state via `XRSTOR`.
Save area: 832 bytes (x87 + XSAVE header + AVX), 64-byte aligned.

aarch64::
The kernel clears the FPU enable bit in `CPACR_EL1` after a context switch.
The first NEON/FP instruction triggers a synchronous trap.
The handler saves/restores Q0-Q31 + FPCR + FPSR.
Save area: 528 bytes, 16-byte aligned.

The `fpu_used` flag on each TCB tracks whether the thread has touched FPU state since the last context switch, avoiding unnecessary saves.

== Sleep Queue

The sleep queue manages threads with timed operations:

* `NanoSleep` (syscall 13): the thread is enqueued with an absolute wakeup time.
* Timed IPC: the thread is in both the endpoint queue and the sleep queue.
* Timed futex: the thread is in both the futex hash table and the sleep queue.

On each timer tick, the scheduler checks the sleep queue head and wakes threads whose deadline has passed.
Whichever event fires first (sleep expiry or partner arrival) wakes the thread; the other reference is cleaned up.

== TCB Operations

[cols="1,1,3"]
|===
| Label | Name | Description

| `0x40` | `TCB_CONFIGURE` | Set VSpace root, CSpace root, IPC buffer, fault endpoint.
| `0x41` | `TCB_RESUME` | Transition from `Inactive` to `Ready`.
| `0x42` | `TCB_SUSPEND` | Transition to `Inactive`.
| `0x43` | `TCB_SET_SPACE` | Set CSpace root and VSpace root separately.
| `0x46` | `TCB_WRITE_REGISTERS` | Write saved register state (IP, SP, arguments).
| `0x48` | `TCB_SET_IPC_BUFFER` | Set IPC buffer virtual address.
| `0x49` | `TCB_BIND_NOTIFICATION` | Bind a notification for combined IPC wait.
| `0x4B` | `TCB_SET_FAULT_HANDLER` | Set fault handler endpoint.
| `0x4C` | `TCB_COPY_FPU` | Copy FPU/SIMD state from another TCB.
| `0x4D` | `TCB_SET_TLS_BASE` | Set TLS base register (`FS` on x86_64, `TPIDR_EL0` on aarch64).
| `0x4E` | `TCB_SET_NOTIFICATION_DISPATCHER` | Set notification dispatcher entry point.
| `0x4F` | `TCB_GET_SPACE_INFO` | Return VSpace, CSpace, and IPC buffer configuration.
|===

NOTE: Labels 0x44, 0x45, 0x47, 0x4A are not assigned.  The numbering is sparse.

== Error Conditions and Edge Cases

=== TCB Destruction While Thread Is Running

When the last capability to a TCB is deleted, `Tcb::cleanup()` runs:

* If the thread is in any wait queue (endpoint, notification, futex, sleep), it is dequeued.
* If the thread is in the ready queue, it is removed.
* Bound notification and bound SchedContext are unlinked.
* If the thread is currently running on a CPU, it is marked `Inactive` and the scheduler switches away at the next reschedule.

=== PIP Chain Depth Limit

Priority inheritance propagates transitively through `pip_donating_to` chains.
To prevent unbounded traversal, propagation is limited to `MAX_PIP_DEPTH` (8 levels).
If a donation chain exceeds 8 links, the boost stops at the 8th thread — deeper holders retain their base priority.

In practice, chains beyond 2-3 are extremely rare (a chain requires A→B→C where each is blocked waiting for the next).

=== PIP With Multiple Donors

The current PIP implementation tracks `pip_donation_count` (number of threads donating to this holder) but only applies the _most recent_ donor's priority.
When `pip_donation_count` drops to 0, the holder's priority reverts to `base_priority`.

This means if two donors with different priorities donate simultaneously, only the last donor's priority is applied.
The correct priority (minimum of all donors) is approximated but not exactly tracked.
This is a known simplification — seL4 has the same limitation.

=== FPU State On Thread Destruction

If a thread with `fpu_used = true` is destroyed, its `XSaveArea` memory is reclaimed with the TCB.
No FPU state leak occurs because the FPU save area is embedded in the TCB struct (not separately allocated).

=== SchedContext Without TCB

A SchedContext can exist without a bound TCB.
It has no effect until bound via `SC_BIND`.
Destroying an unbound SchedContext is a no-op (cleanup finds `bound_tcb = null`).

=== TCB Without SchedContext

A TCB without a bound SchedContext cannot be scheduled.
`TCB_RESUME` on such a thread moves it to `Ready` state, but the scheduler skips threads without a valid SC during dequeue.
